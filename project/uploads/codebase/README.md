# codebase — งานบริหารเวชภัณฑ์ (คลังกลาง) รพ.ตาพระยา

โฟลเดอร์นี้คือหน้าเว็บของระบบในแบบที่ **เปิดได้เองโดยไม่ต้องรันเซิร์ฟเวอร์** (`app/mock-api.js` จำลอง API ในเบราว์เซอร์) ใช้ดูตัวอย่างและเป็นต้นแบบก่อนนำไปใส่ `static/` + `server.py`

| ไฟล์ | คืออะไร |
|---|---|
| `DESIGN-PROMPT.md` | ข้อความสำหรับวางใน Claude Design |
| `app/index.html` | หน้าเว็บ เปิดผ่านเว็บเซิร์ฟเวอร์ใดก็ได้ เช่น `python -m http.server` ในโฟลเดอร์ `app/` |
| `app/app.js`, `app/style.css` | โค้ดหน้าเว็บและสไตล์ (HTML/CSS/JS ล้วน ไม่มี framework ไม่โหลดอะไรจากอินเทอร์เน็ต) |
| `app/mock-api.js` | จำลองเซิร์ฟเวอร์พร้อมข้อมูลตัวอย่าง (6 คลัง, 7 หน่วยเบิก, ทะเบียนผู้เกี่ยวข้อง, ประวัติใบเบิก 12 สัปดาห์) |

| งานผู้ป่วยนอก (OPD) | 3100600054321 | 54321 |
| ห้องฉุกเฉิน (ER) | 1209900067890 | 67890 |
| ผู้ป่วยในชาย | 3340100024680 | 24680 |

## หน้าจอ

- **เข้าสู่ระบบ** — เลขบัตรประชาชน (ขีดคั่นอัตโนมัติ นับหลัก) + รหัสผ่าน 5 ตัวท้าย
- **เบิกสินค้า** — เลือกคลัง → ใส่ตะกร้า (ตะกร้าเดียวใช้ร่วมทุกคลัง) → ใบเบิก: รายการแยกตามคลัง, ประเภทการเบิก (ฉุกเฉิน / ตามรอบปกติ รายสัปดาห์ — บังคับเลือก), ผู้เบิก ผู้อนุมัติ ผู้จ่าย ผู้รับ (เลือกชื่อและตำแหน่งจากทะเบียน เพิ่มใหม่ได้), หมายเหตุถึงคลังกลาง → ส่งแล้ว
- **ใบเบิกของหน่วยงาน** — แก้ไขหรือยกเลิกได้เฉพาะใบที่ "รออนุมัติ"
- **ทะเบียน** — ผู้เบิกสินค้า, ผู้รับสินค้า, หน่วยเบิกในรพ. (+ เจ้าหน้าที่คลังกลาง และบัญชีผู้ใช้ สำหรับ Admin)
- **Dashboard** — ความถี่การเบิกฉุกเฉินรายสัปดาห์, สถิติตามคลัง, หน่วยงานที่เบิกมากสุด, สินค้าที่เบิกมากสุด
- **อนุมัติและสรุปการเบิก (Admin เท่านั้น)** — ตารางรวม สินค้า × ใบเบิก แก้จำนวนอนุมัติได้ เทียบยอดรวมกับคงเหลือ (เกินแล้วอนุมัติทั้งหมดไม่ได้), อนุมัติทีละใบ/ทั้งหมด, ยกเลิกอนุมัติ, ดาวน์โหลดสรุปเป็น PDF (ผ่านหน้าพิมพ์ของเบราว์เซอร์ → "บันทึกเป็น PDF")
- **ใบเบิก / จ่ายสินค้า, สินค้า/สต็อก, ประวัติสต็อก (Admin)** — จ่ายของ เลือกผู้จ่าย/ผู้รับจากทะเบียน

## สิ่งที่ต้องเพิ่มใน `server.py` (ตรงกับ `mock-api.js`)

**ตารางใหม่ / ฟิลด์ใหม่**

- `warehouses` (id, code, name, initials, hue, description) — `items.warehouse_id` แทน `category`
- `departments.code`, `departments.group_name`; `GET /departments` คืน `requester_count`, `receiver_count`
- `people` (id, kind = `requester` | `receiver` | `central`, full_name, position, department_id) — หน่วยงานเห็น/แก้ได้เฉพาะของตัวเอง, `central` แก้ได้เฉพาะ Admin
- `positions` (id, name, scope = `dept` | `central`)
- `requisitions.req_type` (`emergency` | `routine`, บังคับ), `requester_position`, `approver_position`, `issuer_position`, `receiver_position`; `approver_name`/`issuer_name`/`receiver_name` ส่งมาตั้งแต่ตอนสร้างได้ (ไม่บังคับ)
- ใบเบิก 1 ใบมีสินค้าจากหลายคลังได้; `GET /requisitions` คืน `warehouses` (ชื่อคลังในใบ) และ `department_code`; บรรทัดคืน `warehouse_id`, `warehouse_name`

**API ใหม่**

| API | ใช้ทำอะไร |
|---|---|
| `POST /login` | `username` = เลขบัตร 13 หลัก, `password` = 5 ตัวท้าย |
| `GET /warehouses` | รายชื่อคลัง |
| `GET/POST /people`, `PUT/DELETE /people/:id` | ทะเบียนผู้เกี่ยวข้อง (`?kind=`, `?department_id=`) |
| `GET/POST /positions` | ทะเบียนตำแหน่ง (`?scope=`) |
| `PUT /requisitions/:id` | หน่วยงานแก้ใบเบิกที่ยัง `pending` (ส่งข้อมูลชุดเดียวกับตอนสร้าง) |
| `GET /requisitions/board` | Admin: ใบ `pending` + `approved` พร้อมบรรทัด |
| `POST /requisitions/:id/unapprove` | Admin: `approved` → `pending` |
| `GET /analytics` | ข้อมูล Dashboard 12 สัปดาห์ |

ถอด "เปลี่ยนรหัสผ่าน" ออก เพราะรหัสผ่านกำหนดเป็นเลข 5 ตัวท้ายของบัตร
